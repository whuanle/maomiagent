# 工作区下拉过滤设计

## 背景

Git 模块、微信模块、飞书模块中的工作区下拉当前直接使用 `listDesktopWorkspaces()` 返回的全量工作区。由于微信/飞书用户会自动生成专属工作区，这些用户工作区也会出现在普通工作区选择器中，导致下拉内容混杂。

## 目标

- Git 模块工作区下拉只显示普通工作区。
- 微信模块“切换范围”下拉只显示普通工作区。
- 飞书模块“切换范围”下拉只显示普通工作区。
- 不修改工作区存储结构，不新增数据库字段。

## 方案

新增一个共享过滤函数，输入 `DesktopWorkspaceItem[]`，输出仅包含普通工作区的结果。

过滤规则：

1. 如果 `directoryPath` 命中 `.../desktop/workspaces/channels/wechat/...` 或 `.../desktop/workspaces/channels/feishu/...`，判定为外部渠道用户工作区，过滤掉。
2. 如果 `workspaceId` 以 `wechat-` 或 `feishu-` 开头，也判定为外部渠道用户工作区，过滤掉。
3. 其余工作区保留。

双重判断的目的是兼顾现有自动生成规则和历史数据，避免仅依赖单一字段导致漏判。

## 改动范围

- 在桌面端主视图层新增共享工作区过滤工具。
- Git 页生成工作区下拉前先过滤。
- 微信页生成工作区下拉前先过滤，并继续用过滤后的列表推导默认执行工作区。
- 飞书机器人配置面板生成工作区下拉前先过滤。

## 错误处理

- 如果过滤后没有普通工作区，Git 页保持现有空状态行为。
- 微信和飞书保留下拉为空的现有行为，不额外添加说明性文案。

## 测试

- 为共享过滤函数补单测，覆盖普通工作区、微信用户工作区、飞书用户工作区、历史前缀命名数据。
- 为页面回归补断言，确认微信/飞书用户工作区不会出现在 Git、微信、飞书相关下拉中。
