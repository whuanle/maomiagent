# UI 设计师模块设计

## 背景

当前产品虽然已经具备 AI 对话、工作区、智能体与桌面本地运行能力，但缺少一个真正面向前端落地的“UI 设计工作台”。

用户希望新增一个独立的 `UI 设计师` 模块，解决“现有 UI 设计软件虽然带 AI，但生成结果难以直接落地到真实项目”的问题。这个模块不是一个静态设计面板，也不是让用户跳回 `AI 对话` 页面聊天，而是一个在同一工作台中完成以下闭环的产品能力：

1. 在模块内直接使用固定内置的 `UI 设计师` 智能体对话。
2. 一边通过内置清单和对话逐步完成技术栈、主题、组件、布局、页面等设计。
3. 一边在右侧预览真实运行中的本地预览项目。
4. 在规划完成后，一次性生成一个真正可运行、带代码的前端项目模板。
5. 生成后仍然可以继续修改设计，再次生成。

同时，这个模块必须适配开放式技术栈输入。用户可能使用 React、Vue 或其它框架，也可能使用 Ant Design、Element Plus、Naive UI 等不同 UI 框架。系统需要先自动推断；如果无法可靠识别，则要求用户补充文档地址、starter 或参考资料，而不是硬猜。

## 目标

- 新增一个独立的原生主界面模块 `UI 设计师`。
- 在该模块内复用 AI 对话核心能力，但固定绑定内置 `UI Designer Agent`，用户无需切回 `AI 对话` 页面。
- 采用“三栏工作台”结构：
  - 左侧：工作区与多会话
  - 中间：流程、任务、内置清单、设计状态
  - 右侧：本地运行预览
- 一个 `UI 设计师` 工作区对应一份共享设计稿，允许多个对话线程围绕同一设计稿协作。
- 设计稿不局限于单一 Markdown，而是一组可持续编辑、可再生成的设计资产。
- 正式生成前先完成规划与设计稿整理，正式生成时一次性输出真实模板项目。
- 设计阶段维护临时预览工程，正式生成后保留正式产物，并允许继续调整再生成。
- 在工作区级别提供“进行中任务锁定”，防止切换工作区导致设计包、预览和生成状态错乱。

## 非目标

- 本次设计不实现一个通用的 Figma / Sketch 替代品，不做自由画布式设计工具。
- 不在第一版支持“任意未知技术栈零约束高质量生成”；超出系统识别能力时必须要求用户提供补充资料。
- 不把 `UI 设计师` 做成 `AI 对话页` 的简单皮肤替换。
- 不在本次设计中定义所有具体主题风格和所有组件变体的完整美术规范，只定义工作流、数据模型和生成机制。
- 不做后台分布式任务调度，也不做跨设备同步设计稿。

## 方案选择

### 方案 A：直接复制 AI 对话页并局部改造

把现有 `chat` 模块整体复制一份，在其上追加 UI 设计清单、预览与项目生成功能。

优点：

- 前期上手快。
- 多会话、工作区、消息流等能力几乎都已存在。

缺点：

- `chat` 模块已经较重，直接复制会形成第二套难维护的对话工作台。
- 中间流程区、设计包、正式生成和预览逻辑会被挤压成“聊天页附属功能”。
- 后续 UI 设计师和通用聊天的演进边界不清晰。

### 方案 B：复用对话能力内核，独立实现 UI 设计师工作台

新增独立 `ui-designer` 模块。左侧会话、工作区与运行能力复用现有对话内核和桌面桥接能力；中间与右侧按 UI 设计工作台重新组织。

优点：

- 用户心智清晰，进入的是一个专门的设计工作台，而不是第二个聊天页。
- 可以围绕“设计包、内置清单、临时预览、正式生成”建立稳定数据结构。
- 后续扩展技术栈适配器、设计资产格式与项目生成链路时边界更清楚。

缺点：

- 需要新建独立模块和一组新的桌面服务。
- 需要主动抽取和复用聊天内核能力，而不是直接照搬。

### 方案 C：把 UI 设计师做成 ChatPage 的专用模式

在现有 `chat` 模块中增加一种会话模式或智能体模式，然后为该模式增加中栏和右栏附加面板。

优点：

- 复用量最大。
- 路由层变化最少。

缺点：

- 无法建立清晰的独立产品入口和独立工作区心智。
- 容易退化成“在聊天页里塞很多设计附属面板”。
- 设计包与项目生成更难形成稳定的一等能力。

### 结论

采用方案 B。

原因：

- 它同时满足“独立菜单入口”“固定内置智能体”“多会话共享设计稿”“三栏工作台”“设计包真相源”“临时预览与正式生成并存”这几项核心要求。
- 复用现有对话与工作区基础设施，但不被现有聊天页布局和心智束缚。

## 总体设计

模块由四个核心对象组成：

1. `Designer Workspace`
   - 对应一个独立工作区目录。
   - 承载设计包、临时预览工程、正式生成项目和运行时状态。
   - 管理“当前是否允许切换工作区”的锁定状态。

2. `Designer Conversation`
   - 对应左侧多会话线程。
   - 固定使用内置 `UI Designer Agent`。
   - 所有会话共享同一份设计包，只是讨论不同主题或不同分支。

3. `Design Package`
   - 是设计的真相源，不是单条消息，也不是单个 Markdown。
   - 由主规格书和多个结构化文件共同构成。
   - 正式生成、临时预览刷新和后续再生成都读取这组文件，而不是直接读取聊天记录。

4. `Preview Runtime / Generated Project`
   - 临时预览工程：服务设计阶段。
   - 正式生成项目：服务最终交付与二次开发。
   - 两者都位于同一工作区下，互不覆盖。

## 页面结构

`UI 设计师` 页面使用三栏骨架，并全部支持拖拽调整宽度。第一版中栏采用“一体纵向结构”，不额外拆成上下两层独立布局。

### 左栏：工作区与多会话

职责：

- 显示当前 UI 设计师工作区。
- 显示并切换当前工作区下的多个设计对话线程。
- 新建会话、重命名会话、归档会话。
- 显示当前工作区是否处于运行中锁定状态。

规则：

- 会话能力体验尽量与现有 `AI 对话页` 对齐。
- 当前工作区有关键任务运行时，禁止切换工作区。
- 多会话共享同一份设计包，不允许默认创建多个互相隔离的设计稿。

### 中栏：流程、任务、内置清单、设计状态

职责：

- 展示固定主阶段。
- 显示智能体补充的当前任务与缺失项。
- 展示用户已勾选和未勾选的内置清单。
- 显示当前设计稿整理状态、缺失资料和生成 readiness。

规则：

- 主阶段固定，子任务动态生成。
- 用户可选择全部或部分生成项，不强制全量。
- 中栏必须清楚告诉用户“还缺什么、为什么现在还不能生成”，而不是等用户点击生成才报错。

### 右栏：预览侧边栏

职责：

- 以侧边栏浏览器形式展示本地运行项目。
- 支持切换：
  - 临时预览工程
  - 最近一次正式生成项目
- 可附带最小必要的运行状态、端口信息和重新启动预览操作。

规则：

- 设计阶段优先看临时预览工程。
- 正式生成后可切换查看正式项目。
- 右栏主要承载真实运行预览，不承担大段说明性文案。

## 工作流设计

采用“固定主阶段 + 智能体动态子任务”的混合工作流。

### 主阶段

1. `技术栈确认`
   - 收集前端框架、UI 框架、包管理器、构建工具、语言偏好、样式方案、图标方案。
   - 若系统推断不稳，则要求用户补充文档地址、starter 或参考资料。

2. `生成范围勾选`
   - 展示内置清单，允许用户选择全部或部分。
   - 至少包含：主题、多语言、通用组件、表单、表格、筛选栏、分页、弹窗、抽屉、侧边栏、整体布局、登录布局、通用页面、导航、路由、权限占位、示例数据、预览页等。

3. `主题与设计系统`
   - 统一主题 tokens、颜色、圆角、阴影、边框、间距、字体、图标风格、背景和状态色。

4. `局部组件与局部模式`
   - 统一按钮、输入框、选择器、表单组、校验反馈、表格、筛选栏、分页、标签、空状态、加载态、弹窗、抽屉、侧边栏等模式。

5. `整体布局与页面模板`
   - 定义主应用布局、登录布局、空白布局等。
   - 确定登录页、注册页、列表页、详情页、设置页等是否生成。

6. `多语言与内容规范`
   - 若启用 i18n，定义默认语言、资源组织和文案约定。

7. `设计包整理与生成前校验`
   - 整理结构化设计资产。
   - 校验缺项、冲突和资料不足。

8. `正式生成项目`
   - 一次性生成真实模板项目并启动预览。
   - 生成后允许继续调整并再次生成。

## 设计包设计

设计包不局限于单一 Markdown。建议目录结构如下：

```text
<designer-workspace>/
  design/
    design-spec.md
    stack.json
    scope.json
    theme.json
    patterns.json
    layouts.json
    pages.json
    sources.md
    generation-log.md
  preview-app/
  generated-app/
  runtime/
```

### 文件职责

- `design/design-spec.md`
  - 主规格书。
  - 面向人阅读与审查。
  - 汇总技术栈、范围、主题、组件、布局、页面、生成策略和风险约束。

- `design/stack.json`
  - 技术栈真相源。
  - 包含框架、UI 库、构建工具、包管理器、样式方案、图标策略、文档来源等。

- `design/scope.json`
  - 用户勾选的生成范围。

- `design/theme.json`
  - 主题风格、设计 tokens、色板、字体、圆角、阴影、图标风格。

- `design/patterns.json`
  - 局部组件与局部模式规范。

- `design/layouts.json`
  - 整体布局、登录布局和其它框架级布局定义。

- `design/pages.json`
  - 要生成的通用页面模板列表与页面级约束。

- `design/sources.md`
  - 外部文档地址、starter 仓库、用户补充资料。

- `design/generation-log.md`
  - 每次生成的时间、结果、失败点和预览信息摘要。

### 真相源规则

- 对话内容不是生成真相源。
- 所有正式生成、临时预览刷新和再次生成都以 `design/` 下文件为准。
- 智能体的职责是帮助用户完成并修正设计包，而不是直接跳过设计包写代码。

## 技术栈识别与降级

技术栈允许开放输入，但必须有明确降级规则。

### 识别层级

1. `直接识别`
   - 系统可以明确识别用户所需框架与 UI 体系。

2. `推断并确认`
   - 系统给出候选并请求用户确认。

3. `要求补资料`
   - 无法可靠识别时，要求用户提供文档地址、包名、starter 或参考仓库。

4. `受限生成`
   - 资料仍不足时，仅生成设计包和保守的项目骨架，不承诺高质量组件落地。

### 约束

- 禁止在资料不足时硬猜并直接生成复杂组件系统。
- 所有外部资料来源必须记录进 `sources.md` 或结构化来源字段，避免再次生成时重复追问。

## 生成链路

正式生成前先完成规划，再一次性生成项目。

### 生成前

- 允许一边聊天一边更新设计包。
- 允许维护临时预览工程。
- 不生成正式项目代码。

### 正式生成触发条件

至少满足以下条件：

- 技术栈明确。
- 生成范围明确。
- 主题方案明确。
- 至少一套布局方案明确。
- 页面模板清单明确。
- 外部资料缺口已解决，或用户明确接受受限生成。

### 正式生成后

- 写入 `generated-app/`。
- 安装依赖并尝试启动。
- 更新 `generation-log.md`。
- 保留继续修改设计并再次生成的能力。

## 预览设计

预览分为两个目标：

1. `临时预览工程`
   - 位于 `preview-app/`。
   - 用于设计阶段实时验证主题、组件、布局和页面草图。

2. `正式生成项目`
   - 位于 `generated-app/`。
   - 用于展示最近一次正式生成结果。

### 共存规则

- 临时预览工程与正式项目物理隔离，避免互相污染。
- 右栏允许在两者之间切换。
- 继续修改设计时，优先更新 `preview-app/`，不自动覆盖 `generated-app/`。

## 锁定与状态规则

### 工作区切换锁定

存在以下任一状态时，禁止切换工作区：

- 正在同步设计包
- 正在更新临时预览工程
- 正在正式生成项目
- 正在启动或重启预览服务
- 正在执行依赖当前工作区路径的长任务

### 操作分级

- 永远可用：
  - 查看会话历史
  - 查看设计包内容
  - 查看预览
  - 查看日志摘要
- 弱锁定：
  - 继续聊天
  - 调整清单选择
  - 修正文档来源
- 强锁定：
  - 切换工作区
  - 删除当前设计稿
  - 重新生成正式项目
  - 覆盖预览工程

## 失败恢复

正式生成项目应被建模为可恢复任务，而不是一次性黑盒操作。

### 至少记录

- 当前阶段
  - 安装依赖
  - 写主题
  - 写组件
  - 写布局
  - 写页面
  - 启动预览
- 失败原因
- 已完成步骤
- 最近一次成功生成摘要

### 恢复策略

- 用户可修正设计后重试。
- 可从失败步骤继续。
- 不做默认全量回滚，避免误删已认可产物。

## 与当前仓库的落地方案

### 新增主界面模块

在 `apps/desktop/MaomiAgent/src/mainview/modules/` 下新增独立目录：

```text
ui-designer/
  index.ts
  page.tsx
  page.css
  components/
  hooks/
  services/
  types.ts
```

### 页面层建议拆分

- `page.tsx`
  - 负责三栏骨架、Splitter 尺寸与高层状态注入。

- `components/`
  - `conversation-rail`
  - `designer-flow-panel`
  - `designer-task-panel`
  - `designer-preview-panel`
  - `designer-status-bar`
  - `designer-generate-modal`
  - `designer-source-request-modal`

- `hooks/`
  - `use-ui-designer-shell-state`
  - `use-ui-designer-workspace-state`
  - `use-ui-designer-preview-state`
  - `use-ui-designer-generation-state`

### 复用现有能力

- 复用 `desktop-conversation` 的会话能力。
- 复用 `desktop-workspace` 的工作区能力。
- 复用现有 shell / terminal 能力启动本地项目。
- 复用或承接现有浏览器预览能力展示本地地址。
- 复用 `desktop-agents`，在本模块内固定默认使用 `UI Designer Agent`。

### 新增桌面桥接与服务

建议新增一组独立契约和桌面服务：

- `src/shared/desktop-ui-designer.ts`
- `src/mainview/lib/desktop-ui-designer.ts`
- `src/bun/modules/ui-designer/`

职责包括：

- 创建设计工作区目录
- 读写设计包文件
- 评估生成 readiness
- 维护临时预览工程
- 执行正式项目生成
- 启动和停止预览服务
- 返回当前工作区锁定状态与任务状态

## 路由与菜单

### 路由

在 `mainview/config/titlebar.ts` 中新增原生路由项 `ui-designer`。

### 菜单要求

- 作为独立主菜单出现。
- 不要求用户通过 `聊天 -> 选智能体` 的路径进入。
- 页面标题、状态和空状态文案只服务当前设计任务，不写产品导览式废话文案。

## 文案与界面约束

本模块必须遵守现有工作区规则：

- 首屏直接进入主工作台，不做 dashboard、概览卡和统计卡。
- 启动态、加载态、等待态仅提供最小必要提示。
- 不在等待文案中解释内部实现机制。
- 模态窗避让标题栏，长内容模态默认受 `80vh` 限制。
- 样式使用现有语义化类名与主题变量，不引入 Tailwind 风格心智。

## 测试策略

### 桌面服务测试

- 设计工作区目录创建与恢复。
- 设计包文件读写与结构校验。
- readiness 判定。
- 技术栈识别与资料不足降级。
- 生成任务阶段记录与失败恢复。

### 主界面状态测试

- 多会话共享同一设计稿。
- 工作区运行中锁定。
- 右栏在临时预览与正式项目之间切换。
- 任务状态与缺失项提示刷新。
- 固定智能体绑定正确。

### 端到端关注点

- 新建设计工作区后可立即开始对话。
- 用户选择部分清单时，生成范围正确收敛。
- 正式生成后项目能成功启动预览，或在失败时给出可恢复状态。

## 风险与约束

- 开放技术栈输入会带来识别与生成质量波动，必须坚持“资料不足不硬猜”的策略。
- 若临时预览和正式项目共享目录，容易互相污染，因此必须物理隔离。
- 若继续直接依赖聊天消息作为生成输入，多会话场景下会迅速失控，因此必须坚持设计包真相源原则。
- 工作区锁定过宽会影响可用性，过窄会导致状态错乱；第一版应只锁定破坏一致性的关键动作。

## 实施阶段建议

建议按以下顺序实施：

1. 路由、页面骨架和左中右三栏框架。
2. 固定智能体绑定与会话复用。
3. 设计包文件模型与桌面桥接。
4. 中栏固定主阶段、清单与 readiness 计算。
5. 临时预览工程与右栏本地预览。
6. 正式项目生成、日志记录与失败恢复。

这样可以先把工作台骨架和设计真相源建立起来，再逐步接入更重的生成链路。
